# [Leetcode 1：两数之和](https://github.com/lihe/MyLeetcode/issues/25)

[1. 两数之和](https://leetcode.cn/problems/two-sum/)

这是**哈希表思想的“第一性原理题”**，也是面试里**最常被当作“判断你是否会用哈希”的题**。



我按 **暴力 → 优化思路 → 标准解 → 面试话术** 来讲，一步到位。



------





## **一、为什么暴力是 O(n²)？**





最直接的想法：

```
枚举每一个 nums[i]
  再枚举 nums[j]（j > i）
    看 nums[i] + nums[j] 是否等于 target
```



- 两层循环
- 时间复杂度：**O(n²)**





👉 面试官问的“进阶”，就是：

**能不能把第二层循环干掉？**



------





## **二、核心优化思想**





> **我在找 nums[i] + nums[j] = target，**

> **等价于：**

> **我在找 nums[j] = target - nums[i]**



所以问题变成：



> **我之前见没见过这个“差值”？**



这正是 **哈希表擅长的事情**。



------





## **三、哈希表解法**







### **思路**





- 从左到右遍历数组

- 对当前数 x = nums[i]

- 计算需要的另一个数：need = target - x

- 如果 need 已经在哈希表里：

  

  - 说明之前某个位置 j 满足
  - 直接返回 [j, i]

  

- 否则：

  

  - 把当前数和下标存进哈希表

  





------





## **四、标准 Python 实现（面试最稳）**



```python
class Solution:
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        mp = {}  # value -> index

        for i, x in enumerate(nums):
            need = target - x
            if need in mp:
                return [mp[need], i]
            mp[x] = i
```



------





## **五、用示例走一遍**







### **示例 1**



```
nums = [2,7,11,15]
target = 9
```

| **i** | **x** | **need** | **哈希表** | **动作**          |
| ----- | ----- | -------- | ---------- | ----------------- |
| 0     | 2     | 7        | {}         | 存 2:0            |
| 1     | 7     | 2        | {2:0}      | 找到 → 返回 [0,1] |

## **六、为什么不会用到“同一个元素两次”？**





因为：



- 我是**先查，再存**
- 当前元素 x 只有在**下一轮**才可能被用到
- 不可能和自己配对





👉 这是很多人忽略但面试官很喜欢的点

## **七、复杂度分析**





- 时间复杂度：**O(n)**
- 空间复杂度：**O(n)**（哈希表）

## **八、面试一句话总结**





> 使用哈希表记录已经遍历过的数字及其下标，在遍历当前元素时查找是否存在 target - nums[i]，若存在则直接返回对应下标，从而将时间复杂度优化到 O(n)。

# **二、哈希表最小实现结构**



```
key → hash(key) → index → bucket → value
```

代码结构一定是：

```python
class HashMap:
    def __init__(self):
        self.capacity = ...
        self.buckets = [...]
```

# **三、核心 1：哈希函数怎么选？**







## **🎯 哈希函数的目标**





你要说清楚这一句：



> 哈希函数的目标是让 key 尽量均匀分布在桶中，减少冲突。



------





## **1️⃣ 整数 key**







### **面试推荐答案**



```
hash = key % capacity
```

你可以补一句：



> capacity 通常选为 **质数**，可以减少模式冲突。



这是**加分点**。



------





## **2️⃣ 字符串 key**







### **标准做法：**

### **多项式 Rolling Hash**





你可以直接说这个名字。





### **公式**



```
hash = (hash * base + char) % capacity
```



### **示例代码**



```python
def hash_string(s):
    h = 0
    base = 31
    for ch in s:
        h = (h * base + ord(ch)) % capacity
    return h
```



### **为什么用 31 / 131 / 13331？**





你可以这样答：



> 经验上这些质数可以让字符串分布更均匀，且计算成本低。

# **四、核心 2：冲突怎么解决？**





你必须能说出 **两种**。



------





## **方案一：拉链法（最稳，最常用）**







### **思想**



```
bucket[index] = 一个链表 / 数组
```

所有 hash 到同一 index 的元素，都挂在这个桶后面。





### **优点（你可以说）**





- 实现简单
- 扩容方便
- 工程中最常用（Java HashMap）







### **简化代码示意**



```python
self.buckets = [[] for _ in range(capacity)]

def put(key, val):
    idx = hash(key)
    for k, v in buckets[idx]:
        if k == key:
            v = val
            return
    buckets[idx].append((key, val))
```



------





## **方案二：开放寻址法（进阶）**







### **思想**





> 冲突了就**找下一个空位**

```
idx = (hash + i) % capacity
```



### **常见策略**





- 线性探测
- 二次探测
- 双重哈希







### **你可以补一句（加分）**





> 开放寻址对删除和负载因子更敏感，实现复杂度更高。



------





# **五、核心 3：扩容机制**





你可以这样说：



> 当负载因子（size / capacity）超过阈值（比如 0.75），就进行扩容，一般扩容为原来的 2 倍，并重新 rehash 所有元素。



这是 **Java HashMap 标准设计**。



------





# **六、一个“最小可运行”的手写哈希表（示意级）**



```python
class MyHashMap:
    def __init__(self, capacity=101):
        self.cap = capacity
        self.buckets = [[] for _ in range(capacity)]

    def _hash(self, key):
        return key % self.cap

    def put(self, key, value):
        idx = self._hash(key)
        for i, (k, v) in enumerate(self.buckets[idx]):
            if k == key:
                self.buckets[idx][i] = (key, value)
                return
        self.buckets[idx].append((key, value))

    def get(self, key):
        idx = self._hash(key)
        for k, v in self.buckets[idx]:
            if k == key:
                return v
        return -1
```
